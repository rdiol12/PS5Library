## ShellUI agent-indicator startup resilience - 2026-10-10

- **ROOT CAUSE FIXED IN SOURCE:** the ShellUI indicator's process snapshot used a two-call `sysctl(KERN_PROC)` sequence with no retry. ## Account isolation and 20-client capacity pass - 2026-10-08

- **ADMIN-ONLY PACKAGE CREATION:** only a user's current `ADMIN` role may enqueue, retry or execute a BUILD/FPKG conversion. The queue rechecks the role when claiming work, so demoting an administrator stops an already-queued build with `ADMIN_REQUIRED` instead of leaving a hot-looping job. Members can browse shared catalog entries and install or download existing verified artifacts; they cannot create a new package. The browser hides preparation controls from members.
- **QUEUE AUTHORITY AND ISOLATION:** a `MEMBER` cannot reorder a mixed queue containing BUILD work. Queue-position ranking now scopes the ranked subquery to the authenticated user.
- **SHARE REVOCATION FIXED:** catalog history may retain a missing/stale console entry, but source bytes, cached artifacts, compatibility files, native package streams and icon grants now require current owner/global/explicit sharing through `game_content_access`. Revoking an explicit share immediately returns 404 for those byte routes even if the recipient still has an old console-library row.
- **WRITE AMPLIFICATION REDUCED:** unchanged capabilities, diagnostics, pairing state, storage, inventory metadata, trophy summaries and normal heartbeat payloads no longer rewrite rows; an unchanged trophy summary also leaves its sync timestamp unchanged. Both agent loops honor the server heartbeat cadence, cache full scans for 60 seconds and upload full inventory only on first sync or a revision change. Console and save inventory use set-based PostgreSQL reconciliation with bounded SQL round trips. Download progress persists at one-second cadence; native Range callbacks merge in memory with at most one progress transaction per job and drain on shutdown.
- **LIVE READ LOAD REDUCED:** idle WebSocket job polling is two seconds, active polling is 500 ms, session authority is rechecked every 30 seconds and slow clients are disconnected. Browser save polling remains five seconds while browser and iOS full-snapshot fallbacks run every 30 seconds. At 20 idle clients, event queries fall from roughly 40-80 per second to 5.3-10.7 per second.

- **DATABASE AND DELIVERY HARDENING:** PostgreSQL connections now have finite connection, statement, lock and idle-transaction timeouts while migrations explicitly disable those limits inside their own transaction. The installation coordinator performs slow planning and queue enqueue outside transactions, and a cancelled installation cannot be resurrected. Source retirement and artifact/backport cleanup keep verification and recursive deletion outside the short state-check, staging-rename and metadata transactions. Caddy access logging is disabled so native package capability tokens carried in URL paths are not persisted; API logs retain only route templates.

## Watched-dump identity and queue recovery - 2026-10-08

- **ROOT CAUSE FIXED:** FPKG identity now hashes only files the package builder can consume. Top-level backport, fakelib and DLC trees retain a separate full-source hash, so adding compatibility files regenerates the exact overlay/profile without invalidating or rebuilding an unchanged clean FPKG.
- **EXPLICIT VERIFIED RETIREMENT:** after the exact FPKG and required backport have been verified, an administrator can retire and delete one watched dump. The request rechecks source, package and backport bytes, refuses active jobs/installations, and keeps the verified package, backport and catalog release usable. Later scans do not reopen the retired source; rebuilding requires restoring it if the retained artifacts are removed.
- **NO AUTOMATIC SOURCE DELETION:** build completion keeps the dump because another profile or build method may still need it. Deletion requires the explicit administrator retirement request.
- The scanner no longer stops discovering new dumps while another BUILD is active. Baldur's Gate 3 and CODE VEIN II both completed with the corrected base-content identity.
- BUILD cancellation now propagates to only that worker request. Startup also tolerates inaccessible terminal workspaces, and Windows setup uses a Docker Desktop-compatible container identity. Two legacy permission-bound cache/log paths were preserved under stale names; the server recreated writable paths and the stalled trailer task completed.
